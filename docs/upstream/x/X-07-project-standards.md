## 1. 設計書の書き方

- 置き場所: 上流工程の書類は `docs/upstream/` の下に、工程ごとに `rd/`、`bd/`、`dd/`、横断は `x/` に置き、ファイル名は雛形と同じにする。仕様書は `docs/specs/`、設計判断は X-02 の中に置く。
- 版の付け方: 書いたら 0.1 から始め、直すたびに 0.1 ずつ上げる。承認で 1.0 にする。
- 文体: 人が読む書類は、本人の共通のハーネスの決まり（yomiyasu の規則）で書く。主語と対象を省かない。比喩の動詞と、AI らしい言い回しを使わない。
- 案件で足す書き方: 書類の冒頭に、読んだ書類と版、書いた AI を書く（05-ai-authoring-rules 3章「読む上流」）。

## 2. 命名規約

物理名は、X-03 の英語名を使う。X-03 に英語名が無い語は、使う前に X-03 に足す。つなぎ方（下線か大文字か）は、基本設計で言語と DB が決まった後に、ここに足す。

| 項目 | 決まり |
|---|---|
| テーブル名・カラム名 | 基本設計で DB が決まった後に決める（依頼 11章で DB は未決定） |
| モジュール名 | 基本設計で構成が決まった後に決める |
| API の名前 | 配信元から受け取る API は、今の cerebellum の形に合わせる（Q-039 の答え）。それ以外は基本設計で決める |
| 内部のエラーコード | DD-06 で決める |
| ジョブ名 | DD-08 を X-06 で省いた。バッチ（FN-021、FN-022）の名前は BD-02 のバッチの節で決める |
| 略語 | PWA、HUD（X-03）。使う前にここと X-03 に足す |

## 3. コーディング規約

- 使う規約: 言語とフレームワークの公式の規約に従う。フォーマッタとリンタの設定ファイルはリポジトリに置き、実装の前に AGENTS.md に書く。
- 案件で足す決まり（依頼から。X-06 の A18）:
  - AI を動かす CLI は、コマンドの文字列をつなげて起動しない。引数の配列と標準入力で渡す（依頼 7章）。
  - 生成された HTML や届いた内容を、`dangerouslySetInnerHTML` で画面にそのまま埋め込まない（依頼 8章）。
  - 架空のサンプルデータを、本当のニュースとして扱わない（依頼 0章）。
  - 依頼に無い認証の方式、課金の方式、生成の頻度、AI のモデルの名前を、勝手に決めない（依頼 0章）。
- セキュアコーディング規約: 届いた内容と質問を受けるので必要。RD-12 の NFR-016〜NFR-019 に従い、基本設計の BD-10 で具体的な規約を足す。
- 確かめ方: フォーマッタとリンタは検証のコマンドに入れる。
