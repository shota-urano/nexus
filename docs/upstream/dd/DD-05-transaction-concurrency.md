## 1. 方針

前提: DB は SQLite の1つのファイルで、Web サーバ、AI Runner、定期ジョブ、管理のコマンドの4つのプロセスが同じファイルを読み書きする（ADR-007、ADR-008、DD-01）。SQLite は、書き込むトランザクションを同時に1つしか動かさない。

| 項目 | 決まり |
|---|---|
| 接続の設定 | M21（DD-01）が接続のたびに、`journal_mode` を WAL、`foreign_keys` を ON、`busy_timeout` を 5,000 ミリ秒にする。WAL にするのは、読む処理（画面の表示、SSE の続きの読み出し、バックアップ）が書く処理を止めず、書く処理も読む処理を止めないようにするためである（NFR-001、BD-02 5.4 並行稼働） |
| 既定の分離レベル | SQLite のトランザクションは直列化可能（SERIALIZABLE）だけで、選べない。書き込むトランザクションは `BEGIN IMMEDIATE` で始め、始めた時点で書き込みの権利を取る。読むだけの処理は、1つの文で済むものはトランザクションを使わず、2つ以上の文で同じ時点の値を読みたいもの（FN-003、FN-020）は `BEGIN`（DEFERRED）で読む |
| 既定の排他の方式 | 条件付き更新。更新の条件に、遷移前の状態や今の値を入れ（`WHERE state = 'queued'` など）、更新した行の数が 0 なら、ほかの処理が先に変えたと判断する。書き込みの権利が1つなので、`BEGIN IMMEDIATE` の中で読んでから書けば、そのあいだにほかの書き込みは入らない。行のロックや版の番号は使わない |
| ロックを取る順番 | 該当なし。SQLite はデータベースの全体に1つの書き込みの権利を取るので、行ごとのロックの順番が無く、互いに待ち合って止まることが起きない。書き込みの権利は `BEGIN IMMEDIATE` で最初に取り、読む権利から書く権利へ途中で上げない（途中で上げると `SQLITE_BUSY` を待たずに返すため） |
| ロックを待つ時間の上限 | `busy_timeout` の 5,000 ミリ秒。最も長い書き込み（FN-001 の 100 件、BAT-002 の1か月分）でも1秒に満たない見込みで（DD-03 4章の件数）、それより十分に長くし、待ちきれないのは異常な場合だけにする。待ちきれなかったら、DD-06 の分類「DB が使えない」として扱う |
| トランザクションの長さの決まり | トランザクションの中で、AI の CLI（IF-004）を待たない、SSE の送信を待たない、ファイルの書き出しを待たない。AI Runner は、CLI を呼ぶ前と、結果を受けた後にだけ、短いトランザクションを使う（DD-02 3章 P06）。応答の続きの書き足しは、100 ミリ秒ごとの1つの短い更新にする（DD-02 FN-015） |

## 4. 二重実行と再送の防止

| 項目 | 決まり |
|---|---|
| 画面からの二重送信 | 画面は「送る」「完了」「送り直す」を、押してから結果が出るまで押せなくする（BD-09 5章 誤操作の防止）。サーバの側では、「送る」は 3章の作成中の応答の確かめで、「送り直す」は条件付き更新で2回目を見分ける。「完了」は置き換えなので、2回届いても結果は同じになる（DD-04 3.2）。会話の作成（`createConversation`）は2回目を見分けず、会話が2つできることを受け入れる（DD-04 3.2） |
| 冪等性 | 配信元の受け取りは、業務の一意な値で2回目を見分ける。ニュースは対象日と slug、英語は日付で、同じものは置き換える（DD-02 FN-001、FN-007。NFR-015）。要求ごとの番号は持たない（配信元は本人のものだけで、置き換えで足りるため）。受け取りの記録は送られるたびに1件作る（DD-04 3.2） |
| バッチの多重起動 | M27 は、業務層の M31（DD-01。RV17-03）を呼び、印を DB の `job_lock` の行で持つ（DD-03。RV16-03）。取るときは、1つの `BEGIN IMMEDIATE` のトランザクションの中で、そのバッチの名前の行を読み、無ければ自分のプロセスの番号と今の日時で作る。あれば、その番号のプロセスが生きているかを確かめ、生きていれば何もせずに戻し、ログに残して終わる（BD-02 5.4）。生きていなければ、前の起動が異常で終わって印が残ったとみなし、同じトランザクションの中で行を自分の番号に置き換える。書き込みの権利は同時に1つなので、2つのプロセスが同時に古い印を見ても、片方だけが置き換えられ、もう片方は置き換えた後の行（生きているプロセス）を読む。行を作るのと番号を書くのは同じ文なので、番号の無い印はできない。終わるとき（異常で終わるときも）は、バッチの名前と自分の番号が両方合う行だけを消す。launchd の起動と本人の手の起動は、同じ印を使う |
| 再処理のときの重複 | BAT-001 は、同じ日の写しを置き換える（作り終えてから名前を替えるので、置き換えの途中で前の写しが消えることは無い。DD-02 FN-021）。BAT-002 は、消し終わった分はもう条件に合わないので、何度動かしても同じ結果になる（BD-02 5.3）。AI の実行の自動の送り直しは、新しい実行を作り、前の実行は失敗のまま残す（BD-02 3章 ENT-009） |
