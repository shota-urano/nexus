# OP08 バックアップを手で取る、取れないときの確かめ方

別のディスクにバックアップ（BAT-001）を手で取り、取れないときの原因を確かめる（BD-11 2章 M04、4章、NFR-023）。

## きっかけ

- バックアップのログに MSG-039 が出た。直近の予定の回（毎日3時）の BAT-001 が MSG-038 で終わっていない（BD-11 M04）。
- 月に1回の定常作業（BD-11 D02）でログを見て、上に当たったとき。
- DB の形を変えるリリースの前（OP02）。
- 別のディスクを新しいものに替えた後（OP11）。

## 手順

本人が Mac mini で行う。

1. 別のディスクがつながっていて、置き場所があるかを確かめる。

   ```sh
   ls -ld "/Volumes/<ディスクの名前>/nexus-backup"
   df -h "/Volumes/<ディスクの名前>"
   ```

   権限が `drwx------`（本人のユーザだけ）であることと、空きの容量があることを見る。置き場所が無いときは、OP11 でディスクを確かめる。

2. バックアップを手で取る。設定を `env` のファイルから読む。

   ```sh
   cd <リポジトリ>
   set -a; . "$HOME/Library/Application Support/nexus/env"; set +a
   node dist/jobs/main.js backup
   echo $?
   ```

   終了コードの意味（BD-02 5.4）:

   - `0`: 写しを取り、古い写しを消した（MSG-038）。
   - `1`: 今日の写しは取ったが、古い写しを消せなかった（MSG-039）。手順 3 へ進む。
   - `2`: 写しを取れなかった（MSG-039）。手順 3 へ進む。

   同じバッチが動いているあいだは、後から起動したものは何もせずに終わる（BD-02 5.4）。

3. 取れないときは、定期ジョブのログ（OP10）で MSG-039 の理由を見る。

   ```sh
   grep -h 'MSG-03[89]' ~/Library/Logs/nexus/job-*.log | tail -n 20
   tail -n 50 ~/Library/Logs/nexus/launchd-job.log
   ```

   - 置き場所に書けない、ディスクが無い: 手順 1 に戻り、ディスクと権限を確かめる。
   - 古い写しを消せない: 置き場所の写しの持ち主と権限を確かめる。
   - DB を開けない: OP04 で Web サーバと DB を確かめる。

4. 直らなければ、開発の担当（AI）に改修を頼む（BD-11 5章）。

## 確かめ方

- 置き場所に今日の日付の `nexus-YYYY-MM-DD.db` があり、権限が `-rw-------` である。

  ```sh
  ls -l "/Volumes/<ディスクの名前>/nexus-backup/"
  ```

- 写しが今日を含めて7日分より多く残っていない。
- 定期ジョブのログに、今日の MSG-038 が出ている。
