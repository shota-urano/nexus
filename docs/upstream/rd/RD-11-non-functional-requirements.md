## 1. 前提と制約

- 業務の規模と時間帯: RD-03 4章。利用者は本人1人、届く内容は1日50件まで、質問は1日10回、配信は毎朝5時と5時半。
- システムの前提と制約: フロントは Next.js と React の PWA、サーバは本人の Mac mini、端末からは Tailscale のプライベートな接続で使う（RD-01 5章、REQ-025）。Mac mini では cerebellum などが動いており、NEXUS はそこに足す（RD-01 5章 前提）。AI を動かす費用は本人の今の Claude の契約の範囲に収める（REQ-024）。守るべき規格や法令は無い（個人の案件で、依頼に挙がっていない。法令は RD-12 1章で見る）。
- 非機能要求グレードのモデル: 使わない。個人の1人用の仕組みで、グレードのモデルシステムに当たるものが無いため。

## 4. 上流との対応

各 NFR の根拠 REQ・FN・IF は、2章の表の「根拠」の列に書いた。検証の受入基準は RD-15 5章の最後の段落に、NFR ごとの AC の番号を書いた。

- RD-03 4章の規模（1日50件まで、質問は1日10回）と NFR-003 の目標値は同じ値である。
- RD-10 のデータ量（IF-001 は1回10件と X のブックマーク、IF-002 は1回1セット）は、NFR-003 の1日50件に収まる。
