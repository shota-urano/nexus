## 1. 方針

| 項目 | 決まり |
|---|---|
| 基本方針 | BD-01 6章のエラー処理の方針を、次のように分類に当てはめる。本人の端末の操作の失敗は、本人に MSG を見せて押し直してもらう（E01〜E08、E16）。配信元からの受信の失敗は、理由を返して配信元に送り直してもらい、NEXUS からは取りに行かない（E01〜E03、E08）。AI の実行の失敗は、時間の上限、形が読めない、途中で止まったときだけ1回自動で送り直し、AI を動かす仕組みが使えないときは送り直さない（E09〜E13）。バッチの失敗は、ログに出して終了コードで知らせ、本人が手で動かし直す（E14、E15、E08） |
| 握りつぶしの禁止 | 例外を受けて何もしないことを認めない。処理を続けてよい失敗（`markOpened` の失敗、端末の鍵の最後に使った日時を変えられない、断った記録を作れない、BAT-001 の古い写しを消せない）も、分類を決めてログに出してから続ける。ESLint の空の `catch` を禁じる規則（`no-empty`）を検証のコマンドで掛ける |
| 利用者に見せないもの | 内部のエラーの中身（スタックトレース、SQL、ファイルの道、CLI の出力、内部のエラーコード）を、画面と API の応答に出さない。出すのは DD-04 3.4 の `code` と MSG の番号と文言だけにする（BD-10 4章 エラー）。AI の実行の失敗の理由（`ai_run.failure_reason`）は DB とログにだけ残し、画面には MSG だけを出す |

## 2. エラー分類

「分類」の列は分類番号（E01〜E17）である。内部のエラーコードは、英大文字と下線でつなぐ（X-07 2章が DD-06 に送った決まり）。`ai_run.failure_reason` には `<内部のエラーコード>: <短い理由>` の形で入れる（DD-02 3章 P06）。

| 分類 | 分類名 | 見分け方 | 内部のエラーコード | 利用者への見せ方 | 処理の続け方 | ログの重さ |
|---|---|---|---|---|---|---|
| E01 | 入力の誤り | 求めの形が `openapi.yaml` と M10、M15、M16 の zod の形に合わない。配信元の JSON が読めない。カーソルが戻せない | `INPUT_INVALID` | 端末: 400 `bad_request`。画面は操作ごとの MSG（DD-04 3.4。ふだんは MSG-019）を出し、入力値を残す。配信元: 400 と MSG-033（外れた項目の名前） | 止める。何も書かない（ただし配信元は断った記録を作る。DD-02 FN-001） | 情報 |
| E02 | 大きさの超過 | 配信元の本文が上限（IF-001 は 1 MiB、IF-002 は 256 KiB）を超える。IF-001 の記事が 100 件を超える | `INPUT_TOO_LARGE` | 配信元: 413（件数のときは 400）と MSG-034 | 止める。断った記録を作る | 情報 |
| E03 | 鍵が通らない | 端末の鍵、配信元の鍵、登録コードが照合値で見つからない、取り消した、期限を過ぎた、その連携を使えない（DD-02 3章 P01、P02、FN-023） | `AUTH_DENIED` | 端末: 401 と MSG-020。登録の URL: `/?notice=MSG-021` へ移す。配信元: 401 と MSG-032 | 止める。配信元は断った記録を作る | 警告 |
| E04 | 送り元のオリジンが違う | データを変える端末の API で `Origin` が NEXUS のオリジンと違うか無い（BD-10 T17） | `ORIGIN_DENIED` | 403 `forbidden_origin` と MSG-019 | 止める | 警告 |
| E05 | 対象が無い | 内容 ID、会話 ID、発言 ID、日付、端末の名前、配信元で、行が見つからない | `NOT_FOUND` | `getArticle` は MSG-002。英語の教材と会話と発言は MSG-019。`createConversation` は対象の無い会話にして MSG-011。IF-003 は MSG-035 か MSG-036（DD-02 FN-013）。管理のコマンドは MSG-042 | 止める | 情報 |
| E06 | 状態が合わない | DD-05 3章の条件付き更新で更新した行が 0（許されない遷移、同時の操作）。同じ会話に作成中の応答がある | `STATE_CONFLICT` | `postQuestion` は 409 `reply_in_progress` と作成中の発言。`retryReply`、`stopReply`、`dismissReply`、`setRead`、`setSaved` は 200 と今の状態（BD-02 3章 許されない遷移）。AI Runner は何もしない | 止める（取り消すものが無い） | 情報 |
| E07 | 業務の規則違反 | ○△× の無い問題か、セットに無い問題番号がある（FN-012）。同じ名前の端末がある（FN-023）。配信元の名前が値に無い（FN-024） | `RULE_VIOLATION` | FN-012 は 400 と MSG-005。管理のコマンドは MSG-043 か MSG-044 と終了コード 1 | 止める | 情報 |
| E08 | DB が使えない | `node:sqlite` が `SQLITE_BUSY`（5 秒待っても書けない。DD-05 1章）、`SQLITE_FULL`、`SQLITE_IOERR`、`SQLITE_CORRUPT`、`SQLITE_CANTOPEN` を返す | `DB_UNAVAILABLE` | 端末: 500 `internal`。画面は操作ごとの MSG（MSG-003、MSG-007、MSG-019）。配信元: 500 と MSG-045（IF-001）。バッチ: MSG-039 か MSG-041 と終了コード 2 | 止めてトランザクションを戻す | エラー |

| E14 | バックアップの置き場所が使えない | 置き場所のフォルダが無い、書けない、空きが無い、写しを作れない（FN-021） | `BACKUP_TARGET_UNAVAILABLE` | 該当なし（画面と API には出さない）。ログに MSG-039、終了コード 2 | 止める。作りかけの写しを消す | エラー |
| E15 | 古い写しを消せない | 7 日より古い写しを消せない（FN-021） | `BACKUP_CLEANUP_FAILED` | 該当なし（画面と API には出さない）。ログに MSG-039、終了コード 1 | 続ける（新しい写しは残す） | 警告 |

## 3. 障害モデル

## 4. 再試行・タイムアウト・補償

| 依存先・分類 | タイムアウト | 再試行の回数と間隔 | 打ち切った後 |
|---|---|---|---|
| IF-004（E09、E10、E11） | 1回の実行で 5 分（NFR-017）。止めるときは SIGTERM を送り、5 秒たっても終わらなければ SIGKILL を送る | answer と relate だけ、1回だけ自動で送り直す（`attempt` 2 の実行を待ちに入れる。DD-02 3章 P06）。間隔は置かない（待ちに入った順に AI Runner が拾う）。summarize は送り直さず、次の質問の応答の後にもう一度判断する | answer は応答を失敗にし MSG-012。relate はログに MSG-037。どちらもホームに MSG-017（24 時間） |
| IF-004（E12、E13、E16） | 同上 | 送り直さない（DD-02 3章 P06。RV16-02） | 同上（answer は MSG-013 か MSG-012） |
| DB（E08 の `SQLITE_BUSY`） | `busy_timeout` 5,000 ミリ秒（DD-05 1章） | NEXUS の側では送り直さない。SQLite が待つ間だけ待つ | 端末は本人が押し直す。配信元は配信元が送り直す（DD-04 3.2） |
| 端末から Web サーバ（SSE） | 15 秒ごとに空のコメント行を送る（DD-04 3.5） | 画面が `Last-Event-ID` を付けて 3 秒後につなぎ直す（DD-04 3.2）。応答が作成中のあいだ続ける | 画面を開き直すと `getConversation` で読み直す |
| 端末から Web サーバ（そのほかの API） | 画面の側で 15 秒（NFR-001 の 2 秒より十分に長く、Tailscale の遅れを見込んだ値）。超えたら MSG-019 か操作ごとの MSG | 自動では送り直さない（DD-04 3.2） | 本人が押し直す |

- 補償: 使わない。DD-05 5章の複数の資源の整合は、全て順番（DB を先に確定する）と記録で取っており、取り消しの処理は要らない。

## 5. ログ出力

| 項目 | 決まり |
|---|---|
| 重さの段階 | 情報（`info`。正常の記録と、利用者の入力の誤り）、警告（`warn`。続けてよい失敗と、外からの怪しい求め）、エラー（`error`。処理を止めた失敗）、致命的（`fatal`。プロセスが動けない）。通知はしない（Q-009 の答え）。本人は BD-11 の定常作業とホームの知らせで見る |
| 形 | 1行に1つの JSON（M23 のログの関数）。各プロセスが日ごとのファイルに書き、30 日より古いファイルを消す（BD-01 6章。CR-013。置き場所は DD-09 2.6）。開発の環境では標準出力に出す |
| 残す項目 | `at`（日時。DD-02 3章 P09 の形）、`level`、`process`（web、runner、job、cli）、`code`（内部のエラーコード。正常は無し）、`msg`（MSG の番号。あれば）、`target`（FN、BAT、IF の番号）、`requestId`（要求ごとの番号。Web サーバが要求ごとに作る乱数の16進8文字）、`aiRunId`、`contentId` などの対象の ID、`detail`（原因の詳細。例外の種類と文、SQLite のエラーの名前） |
| 残してはいけない項目 | 端末の鍵、配信元の鍵、登録コード、それらの照合値、Cookie と `Authorization` の欄の値、Claude の認証の情報（NFR-019、BD-10 T09）。届いた記事と教材の本文、質問と応答の本文、AI に渡した内容（会話は私的な内容を含むため。中身は DB の発言と写しで追える。BD-01 6章 データ管理）。CLI の標準エラーは、`detail` に入れる前に、鍵の形（43 文字の base64url）と `sk-` で始まる文字列を伏せる |
| 問い合わせ用の番号 | 利用者は本人1人で、画面でエラーを見たときは本人が Mac mini のログを見るので、画面に番号を出さない。ログは日時と操作で探す（BD-11 OP10） |
| 監視の対象 | MSG-037（BD-11 M02 の補助）、MSG-038、MSG-039（M04）、MSG-040、MSG-041（M05）。E08 と E17 のエラーと致命的は、BD-11 OP04 で本人が見る |
