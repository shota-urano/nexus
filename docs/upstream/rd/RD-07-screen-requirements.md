## 2. 代表画面イメージ

- 選んだ画面と理由: SCR-001 ホームと SCR-002 News Galaxy（と SCR-003 記事の案内）。見た目と動きがこの案件の中心で、本人が見た目を選んできたため（依頼 2章「一度縦積みにしたがユーザーは横並びを選好した」）。
- 画面イメージ:
  - SCR-001: `NEXUS_implementation_handoff/references/nexus-home-reference.png`（デザイン画像）と `references/nexus-home-mock-v3-handoff.html`（横並びの HUD の動くモック）。
  - SCR-002 と SCR-003: `references/news-galaxy-reference.png`（デザイン画像）と `references/news-galaxy-mock.html`（図の動きのモック）。
  - 全体の色と質感の元: `references/original-hud-inspiration.jpg`。特定のサービスの画面を写すのでなく、方向性として使う（依頼 12章）。
  - ロゴ: `references/nexus-logo-transparent.png`。
- 粒度の断り: このイメージとモックは基本設計で作り直す。モックの JavaScript とデータの形は本番に使わない（依頼 0章、12章）。画像の中の件数、記事、日付は作り物で、本当のニュースとして扱わない（依頼 0章、2章）。
- 画像と今回の範囲の違い: デザイン画像のホームの「AIタスク 2件実行中」は、Phase 4 のジョブ（範囲外。Q-006 の答え）ではなく、AI の応答の状況（RD-03 R21）として出す。英語の教材は、依頼の iframe でなく NEXUS の表示部品で見せる（X-02 ADR-001）。
- 利用者による表示の違い: 該当なし（利用者は本人だけ。Q-004 の答え）。

## 3. 画面設計方針

- 基本の画面構成: 暗い色を土台に、アンバーとオレンジの光を主に、青、紫、緑を補いに使う。柔らかい光、円形の軌道、細い接続の線、わずかな浮き上がりと奥行き、選んだものの強調を使う（依頼 2章 共通トーン）。ホームの円形 HUD と右のカードは横に並べ、iPad では広さに合わせて大きさと情報の量を増やす（依頼 2章）。具体的な値は BD-09 で決める。
- 画面遷移の型: ホーム（SCR-001）から各機能へ移る。セグメントの光 → カードの移動と奥行き → 広がって画面が移る、の順に動かす（依頼 2章）。ホームで「選ぶ」と「移る」を別の操作にするかは、依頼が UX の検証で決めるとしているので、BD-13 の試作で決める。一覧（SCR-004、SCR-007〜SCR-009）から詳細（SCR-003、SCR-005）へ進む。AI チャット（SCR-006）はどの画面からも重ねて開く。
- エラーの見せ方: AI の応答の失敗は、会話の中に失敗の状態として見せ、送り直しとやめるを出す（RD-03 R15）。完了の保存の失敗は、採点の段に残せなかったことを見せ、答えを預けたままにする（RD-06 UC-010）。データが無いときは0か空の状態を見せる（RD-03 R21）。配信の受け取りの失敗は画面に出さず、Mac mini のログで見る（Q-036 の答え）。
- 入力の負担を減らす: 質問の対象は、開いている画面と選んだ箇所から自動で決め、本人は文面を貼り直さない（RD-03 R13）。
- 誤操作の防止: 既読は未読に戻せ、保存は外せるので、確認を出さない。完了した教材のやり直しは前の答えを置き換えるので、置き換える前に確認を出す（Q-044 の答え）。
- 権限によるメニューの出し分け: 該当なし（利用者は本人だけ。Q-004 の答え）。
- 対応する環境: RD-11 NFR-007（iPad の Safari と Android の Chrome の最新版、幅 360〜430 ピクセルと iPad の幅、縦と横）。
- 準拠する基準: 該当なし（RD-11 にアクセシビリティの基準の要件は無い）。押す場所の大きさと動きを減らす設定への対応は RD-11 NFR-008 に従う。
- 前提とする部品: Next.js と React（RD-11 NFR-011）。Tailwind CSS、Motion、図の描き方（SVG と Motion、React Flow）は依頼が「推奨（未確定）」としているので、基本設計で決める（依頼 3章）。
