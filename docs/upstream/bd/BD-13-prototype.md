## 1. 確かめる問い

| P02 | ホームの左の HUD と右のカードを横に並べたとき、幅 360、375、390、430 ピクセルと iPad の幅の縦と横で、カードの文字と押す場所が HUD に隠れないか | NFR-008 と依頼 10章 Phase 1 の受け入れ基準。画像のモックだけでは、狭い幅での重なりを確かめられない | 5つの幅と2つの向きの全てで、カードの文字と押す場所が隠れず、意図しない横のスクロールが出ない（画面を撮って確かめる） |

## 2. 試作の範囲と作り方

| 項目 | 内容 |
|---|---|
| 対象の画面と流れ | P01、P02、P05: SCR-001 ホーム → 機能の画面（中身は空でよい）。P03: SCR-002 News Galaxy → SCR-003 記事の案内。P04: SCR-005 か SCR-003 → SCR-006 AI チャット。P06: SCR-007 Inbox、SCR-005 の完了の確認。P07: SCR-005 の教材の段。P08: SCR-006 で応答を流す |
| 作り方 | P01〜P07: 実際に動く試作（Next.js と React の画面だけ。BD-01 5章の技術で作る）。端末の動きと幅を確かめるため、画像や紙では足りない。P08: Mac mini で1秒ごとに文字を流すだけの小さなサーバを、Tailscale Serve の試験の名前で公開する |
| 作り込まない部分 | DB、受け取り、認証（端末の鍵）、AI。AI チャットの応答は決まった文を流す。確かめるときに、本人に「データは作り物で、保存されない」と伝える |
| 使うデータ | 作り物の記事10件と過去の記事数件（依頼 10章 Phase 1「ハードコードしたサンプルデータ10件」）、英語のセット1日分。作り物の記事は本当のニュースとして扱わず、画面に「試作」と出す（X-07 3章）。英語の教材は、sharpen の `drills/en/` の既にあるセット1つを写して使ってよいかを本人に確かめる（会話や答えのような私的な情報は含まない。BD-10 1章） |
| 試作物の置き場所と扱い | リポジトリの `prototype/` に置き、本番のコードに流用しない（依頼 12章と同じ扱い）。P01〜P08 の結果を書いた後に、`prototype/` を消すかを本人に確かめる。P08 の試験の名前は、確かめた後に Tailscale Serve から外す |

## 4. 結果

問いごとの結果: 2026-11-24 に本人が iPad と Android で確かめ、「試作はとりあえず問題ない」と答えた。P03〜P05 はその前に本人が選んだ。問いの外で見つかったこと（ホームの見た目を参考の画像とモックに寄せる、右上の惑星、English の同じ英文の重なり、カードの間隔）は、下の表の観察した事実に書いた。

| 問い | 結果 | 観察した事実 |
|---|---|---|
| P01 | 合格（2026-11-24 本人が最終確認。本人の案の「指で回す」形） | 2026-11-24 本人: 1回目は「くるくる回して右真ん中にきたもののカードを表示する」。2回目は「指で回せるイメージ」。指で HUD を回し、離すといちばん近い機能が右の真ん中に合い、その機能のカードが前に出る形にした（セグメントを押しても回る。カードを押すと移る）。AI が 375 ピクセルで指の操作を再現し、約70度回すと隣の English に合うことを確かめた（`prototype/shots/home-375-drag.png`） |
| P02 | 合格（2026-11-24 本人が最終確認） | 2026-11-24 本人: 「スマホのときにくるくるが小さい」、見た目が参考の画像より単調、「UIデザインで必要な画像はcodexに作らせて」「モック HTML も参考になる」「要件にない部品は無視でよい」。ホームの見た目を依頼の資料のモック（`references/nexus-home-mock-v3-handoff.html`）と参考の画像に寄せた（星の背景、金色に光るセグメント、斜めに積んだカード、数の並び、AI に質問、写真付きのピックアップ）。宣伝文、検索と設定、学習連続、ワークスペース、下の帯は要件に無いので入れていない。HUD は画面の幅の約3分の2。中心の球と記事の見本の写真（5枚）は Codex（gpt-image）が作った（`prototype/public/img/`。プロンプトも同じ場所）。本人の希望（「やばい、参考や。右上らへんの地球みたいなんも欲しい」）で、右上に夜の惑星の飾りを足した（Codex が作った `planet_001.png`。背景の飾りで、機能は持たない）。本人の指摘（「スマホ時に右のカードの上下の間隔があきすぎ」）で、幅 480 ピクセル以下では、前のカードの高さを測り、隣のカードをそのすぐ上と下に詰めて並べるようにした（AI が 375 ピクセルで News Galaxy と English を選んだ写真を撮って確かめた）。AI が 375 ピクセルと iPad の縦で写真を撮り、HUD の文字とカードの見出しが隠れないことを確かめた（`prototype/shots/`） |
| P03 | 決まった: React Flow（2026-11-24 本人） | 2026-11-24 本人の答え |
| P04 | 決まった: 下から出る面。iPad も同じ（2026-11-24 本人） | 2026-11-24 本人の答え |
| P05 | 決まった: 下の帯は置かない（2026-11-24 本人） | 2026-11-24 本人の答え |
| P06 | 合格（2026-11-24 本人が最終確認） | 2026-11-24 本人: 教材の本文（lessonMd）を、表を含めて整えて見せてほしい。一覧の時刻は要らない。新着はタグにしてほしい。教材の本文を Markdown（表を含む）として整えて見せ、一覧から時刻を外し、新着をタグにした |
| P07 | 合格（2026-11-24 本人が最終確認） | 2026-11-24 本人: 日本語訳が出ない。新しく出る熟語にはヒントがほしい。今の read.html と同じく、文を押すと和訳を下に出し、注を種類（今日の規則、単語、熟語、文法）ごとに色分けして凡例と「印を隠す」を付けた。熟語は sharpen の `read.json` の注の種類 `phrase` で、色で目立たせ、押すと意味が出る。2026-11-24 本人: 「英語もいい。ただ同じ英文が2箇所に出ている（タップできない方）」。教材の本文の「## 読む」の節に同じ英文があったので、読む教材があるときはその節を出さないようにした（BD-02 FN-009） |
| P08 | 合格（2026-11-24 本人が最終確認。「とりあえず問題ない」） | 2026-11-24 本人: 「よくわからん」。文字が1秒に1語ずつ増えるのを見るだけの画面にし、終わったら合格かを画面に出すようにした。Mac mini から Tailscale を通した確かめでは1秒ごとに届いた |
