## 2. 1行の書き方

- 雛形 DD-11 2章の形式のまま書いた（`- [ ] [担当] やること（設計項目）` と、次の行の `  - 受け入れ基準:`）。
- 担当は `[Backend]`、`[Frontend]`、`（人間）`。人の行には受け入れ基準を書かない。

## 3. 受け入れ基準の書き方

- 合格の条件は DD-10 のテストケースの番号で書いた（番号を範囲で書かない）。
- DD-10 の対象にしない作業（01 のビルドと検証の設定、02 のマイグレーション、06 の service worker の保存の対象、13 の設定の雛形）だけは、条件を直接書いた。手順書は DD-10 TC128 で確かめる（X-05 RV16-09）。どれも、ファイルや DB を見て一つに決まる条件である。
- `make verify` が通ることは書いていない（全ての行の前提）。

## 4. 粒度と並び

- 1行は1つのコミットか1つの PR で終わる大きさにした。API と画面は別の行にした。
- 仕様書の中では、ほかの行が使うもの（入口の土台、待ち行列、共通部品、API の呼び出し）を先に置いた。
- テストを書く作業と実装する作業は同じ行にした（DD-10 のテストケースを、その行の中で書いてから実装する）。

## 5. 既存テストと、テストを弱める失敗への対策

該当なし（新規開発。X-06 で BD-14 を省いた）。実装する作業では、前の行で入れたテストを変えない。
